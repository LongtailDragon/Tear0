# Tear0

Tear0 is a local*, turn-based voice + vision support loop extension for Hermes Agent. It simulates the experience of being on the phone with a tech support agent who is viewing your screen with TeamViewer or a similar screensharing tool.

Flow:
1. Start Tear0 from `Tear0.bat` or `dist/Tear0.exe`.
2. Pick one of your displays for Tear0 to watch.
3. Speak a command.
4. Tear0 screenshots the selected display and sends it, along with a transcription of your voice command, to your Hermes agent.
5. Tear0 reads Hermes response aloud.
6. Continue the conversation loop until your problem is resolved.

Tear0 reduces turn latency for Hermes use cases which require screenshots, i.e. when trying to learn and navigate an unfamiliar Software or Web App's GUI for the first time.

*Tear0 uses local resources for STT and TTS. The Hermes Agent may or may not be running locally depending on your configuration when Hermes was installed.

## Prerequisites

- Windows 10/11
- Python managed by `uv` through the installer
- Hermes Agent installed and working on PATH for live agent calls
- A microphone and speakers/headphones
- Optional: NVIDIA GPU. Tear0 auto-detects CUDA/cuBLAS/cuDNN support and falls back to CPU int8 when CUDA runtime DLLs are unavailable.

## Install on Windows

Double-click:

```text
install.bat
```

Or from PowerShell:

```powershell
git clone https://github.com/LongtailDragon/Tear0.git
cd Tear0
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

The installer:
- checks for `uv`, `hermes`, and `ffmpeg`
- creates `.venv`
- installs Tear0 dependencies
- inspects GPU hardware with `nvidia-smi` when available
- selects `tiny.en` Whisper for low latency
- chooses CUDA float16 only when NVIDIA plus the required CUDA/cuBLAS/cuDNN runtime DLLs are available; on Windows the installer includes the needed `nvidia-cublas-cu12` and `nvidia-cudnn-cu12` Python wheels
- downloads Kokoro ONNX model assets
- can build `dist\Tear0.exe` if you pass `-BuildExe`



NVIDIA GPU support is optional. Tear0 checks whether CUDA/cuBLAS/cuDNN runtime DLLs are actually loadable before choosing CUDA Whisper. If not, it uses CPU int8 automatically.

## Run

```text
Tear0.bat
```

For a safe non-audio check:

```text
Tear0.bat --dry-run
```

### Usage

Stop with Ctrl+C or by exiting the terminal window.

Pause listening:
- press `Ctrl+=` to pause microphone input
- press the same key combo again to resume listening

## Hermes session continuity

Tear0 now keeps one Hermes conversation alive for each app run:

- first voice turn creates a fresh Hermes session
- Tear0 captures the returned `session_id`
- later voice turns use `hermes --resume <session_id> chat ...`

That lets Hermes remember the prior troubleshooting steps from the current support call instead of repeating the same instruction every turn. Restarting Tear0 starts a fresh support-call session.

## Speech detection tuning

Tear0 now requires both:
- multiple consecutive WebRTC VAD speech frames, controlled by `speech_start_frames`
- enough input volume, controlled by `speech_rms_threshold`

If it still triggers when nobody is talking, increase `speech_rms_threshold` in `tear0.config.json` from `500` to `800` or `1000`. If it misses quiet speech, lower it to `300`.

If Tear0 chops off the first word or two, increase `pre_speech_ms` from `450` to `700`. This keeps a short rolling audio buffer before the VAD trigger so the beginning of your command is preserved.

## TTS playback tuning

If Windows clips the end of the last spoken word, increase `tts_tail_padding_ms` in `tear0.config.json`. The default is `400`, which appends 0.4 seconds of silence after Kokoro output before playback ends.

## Local configuration

`tear0.config.json` is generated by the installer for your machine and is intentionally ignored by git. It may contain local hardware detection results and user-specific model/session paths.

Commit `tear0.config.example.json`, not `tear0.config.json`. The `%TEMP%` and `%USERPROFILE%` entries in `tear0.config.example.json` are placeholders; the installer writes resolved paths on each machine.

## Notes

- Latency is prioritized over maximum transcription accuracy; `tiny.en` is intentional.
- This is turn-based, not full-duplex. Kokoro finishes speaking before listening resumes.
- Hermes must already be configured and working on the machine.
- Microphone/speaker/display access is local to the machine running Tear0.
